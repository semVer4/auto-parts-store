# Как AI использовался в этом проекте

Исходная версия была быстрым AI-сгенерированным frontend-прототипом. Этот документ описывает текущую доработку, а не реконструирует несуществующую историю промптов или коммерческий кейс.

## Работа по ролям

- Backend: контракт API, валидация, хранение и тесты бизнес-правил.
- Frontend: интеграция оформления, ошибок и истории заказов, демонстрационные пояснения.
- Документация/QA: критерии приёмки, ограничения, CI и E2E.
- Интеграция: согласование общего контракта, проверка diff, сборки, тестов и публикации.

Независимые части можно выполнять параллельными AI-агентами. Общие типы, статусные переходы и API должны быть согласованы до интеграции; количество агентов само по себе не является показателем качества.

## Инструкции

Конвенции находятся в `AGENTS.md`; `CLAUDE.md` ссылается на те же правила. Изменения ограничиваются задачей; нельзя хранить секреты, подменять реальное сохранение имитацией успеха или объявлять непроверенный deploy успешным.

## Цикл проверки

1. Зафиксировать сценарий и критерии готовности.
2. Проверить фактический код, не полагаться на описание AI.
3. Внести небольшие согласованные изменения.
4. Выполнить `npm run check` и Playwright.
5. Разобрать ошибки, проверить пользовательский путь и ограничения.
6. Отдельно проверить опубликованный Netlify API после deploy.

Документация и наличие тестов не означают, что все команды уже успешно выполнены. Актуальный результат нужно смотреть по конкретному запуску CI/локальных команд. Внешние MCP-сервисы, приватные плагины и платные интеграции не требуются для запуска и здесь не заявляются.
