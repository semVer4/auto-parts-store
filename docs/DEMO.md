# Демонстрация за 3–5 минут

Используйте только синтетические данные: имя `Демо Пользователь`, email `demo@example.com`, телефон `+7 999 000-00-00`. Не вводите настоящие адреса, контакты или реквизиты.

1. **Каталог.** Покажите поиск по артикулу, фильтр бренда и сортировку. Добавьте товар в наличии. У товара «Нет в наличии» добавление в корзину недоступно; сервер также отклоняет его при прямом запросе.
2. **Корзина.** Измените количество, перезагрузите страницу и проверьте состояние. Перейдите к оформлению.
3. **Валидация.** Покажите обязательные контакты и необходимость адреса для доставки. Выберите самовывоз, чтобы обойтись без адреса.
4. **Сохранение.** Подтвердите тестовый заказ. В DevTools → Network найдите POST `/api/orders`: ответ содержит серверные суммы и созданную запись. Реальный платёж не происходит, письмо не отправляется.
5. **Заказы.** Откройте «Заказы», обновите страницу. Заказ должен остаться. Измените статус, проверьте историю, обновите ещё раз.
6. **Изоляция.** Откройте сайт в отдельном профиле/приватном окне: там свой пустой список. Это изоляция демо-сессий, не полноценный вход в аккаунт.
7. **Проверки.** Покажите `npm run check`, `npm run test:e2e` или CI. Не говорите, что тесты проходили в текущей версии, пока это не проверено.

## Что можно честно сказать работодателю

«Исходный интерфейс был быстрым AI-прототипом. В последующей AI-assisted доработке появился серверный сценарий заказа: валидация, цены на сервере, сохранение, изоляция сессий, повторное чтение, переходы статусов и автоматические проверки. Я могу показать код, ограничения и сценарий проверки».

Уточняйте личный вклад фактически: какие решения проверили и можете объяснить сами. Использование AI не означает самостоятельную разработку каждой строки. Не приписывайте проекту коммерческих клиентов, пользователей, выручку или production-эксплуатацию.

## Перед отправкой ссылки

- Проверить опубликованный сайт, а не только локальную сборку.
- Пройти полный путь заказа и перезагрузку.
- Убедиться, что нет неподтверждённых обещаний об оплате/письмах.
- Проверить мобильную ширину и ошибки Console/Network.
- Отправлять опубликованный сайт вместе с GitHub и кратким объяснением ограничений.
