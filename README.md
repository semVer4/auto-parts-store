# АвтоДеталь — AI-assisted full-stack demo

Портфолио-проект магазина автозапчастей: каталог, фильтры, корзина и сквозной сценарий заказа с настоящим серверным сохранением. Интерфейс — React + TypeScript + Vite; API — Netlify Functions; хранилище — Netlify Blobs.

Это **изолированная демонстрационная среда**, не действующий магазин. Платежей, отправки писем, складского учёта и реальных поставок нет. Вводите только тестовые контакты.

## Запуск

Нужен Node.js 22 и npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

Vite использует Netlify plugin для локального выполнения Functions и Blobs. Открывайте адрес, который напечатан в терминале; обычного статического сервера для полного сценария недостаточно.

## Что можно проверить

1. Открыть каталог, отфильтровать товары, добавить доступный товар в корзину.
2. Оформить заказ с вымышленными контактами. Цены, наличие и доставку проверяет сервер.
3. Открыть «Заказы», перезагрузить страницу и убедиться, что запись сохранилась.
4. Изменить демонстрационный статус заказа и просмотреть историю.

Каждый браузер получает собственную HttpOnly-cookie с непрозрачным идентификатором. API возвращает только заказы этой демо-сессии. Это удобная изоляция для просмотра, **не полноценная пользовательская авторизация**. Другой браузер или удаление cookie не дают доступ к прежним заказам.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` последовательно выполняет проверку типов, автоматические тесты и production-сборку. Playwright дополнительно проверяет пользовательский путь и контракт API на desktop и mobile Chromium. CI выполняет оба набора проверок; при падении E2E доступны отчёт и trace.

## Публикация

Подключите репозиторий к Netlify: команда сборки `npm run check`, каталог публикации `dist`. Конфигурация Functions и маршрутов находится в `netlify.toml`. В опубликованном окружении нужен доступ к Netlify Blobs. Ручные секреты для оплаты или почты не требуются: этих интеграций в проекте нет.

Если Git continuous deployment уже подключён в настройках сайта, push в отслеживаемую ветку запускает новую сборку. Сам факт наличия кода в GitHub не подтверждает успешный deploy; проверяйте статус в Netlify и API опубликованного сайта.

GitHub Pages и произвольный статический хостинг не выполняют Functions и не заменяют Netlify для этой версии.

## Границы проекта

Лимит 20 заказов на сессию и ограничение размера запроса не заменяют глобальную защиту от злоупотреблений. Для публичной коммерческой эксплуатации нужны ограничения частоты запросов, полноценная авторизация и политика удаления старых данных.

Каталог и цены демонстрационные. KV-запись изолирована по демо-сессии; условные записи защищают её от конфликтующих обновлений, но это не транзакционная SQL-база и не учёт склада. Нет промышленной авторизации, резервирования остатков и операционного мониторинга. Cookie действует семь дней, но автоматическая очистка сохранённых заказов не реализована. Перед реальным коммерческим использованием нужны отдельные проектирование безопасности, хранилище под бизнес-транзакции, платёжные и почтовые интеграции, правила обработки персональных данных и эксплуатационные процедуры.
